# Day 4 · 반복문

## 왜 배우는가

AI 모델은 "데이터를 보고 → 틀린 만큼 조금 고치기"를 **수천~수만 번 반복**해서 똑똑해집니다. 그 반복을 코드로 쓰는 것이 바로 `for`와 `while`입니다. 그래서 반복문을 이해하면 딥러닝 학습 코드의 뼈대를 읽을 수 있습니다.

---

## 0. 먼저 AI 용어 잡기

오늘 문제와 설명에 나오는 AI 용어를 **시험 공부**에 비유해서 정리합니다. 지금은 "대충 이런 뜻이구나" 정도면 충분합니다. 수학적인 내용은 3단계(Day 57~)와 5단계(Day 106~)에서 제대로 배웁니다.

| 용어 | 시험 공부 비유 | AI에서의 뜻 |
| --- | --- | --- |
| **샘플(sample)** | 문제집의 문제 한 개 | 데이터 한 건 (사진 1장, 문장 1개) |
| **모델(model)** | 공부하는 학생 | 입력을 받아 답(예측)을 내는 함수 |
| **파라미터(parameter)** | 학생 머릿속 지식 | 모델 안의 숫자들. 학습은 이 숫자를 고치는 과정 |
| **손실(loss)** | 채점했을 때 틀린 정도 | 예측이 정답과 얼마나 다른지 나타내는 숫자. **작을수록 좋음** |
| **epoch** | 문제집을 처음부터 끝까지 한 번 다 풀기 | 학습 데이터 전체를 한 바퀴 다 보는 것 |
| **배치(batch)** | 한 번에 푸는 문제 묶음 (10문제씩) | 데이터를 묶어서 한꺼번에 처리하는 단위 |
| **학습률(learning rate, lr)** | 틀렸을 때 공부 방법을 얼마나 크게 바꾸는지 | 파라미터를 한 번에 얼마나 크게 고칠지 정하는 숫자 |
| **검증 손실(val_loss)** | 안 풀어 본 모의고사 점수 | 학습에 안 쓴 데이터로 잰 손실. 진짜 실력 |
| **early stopping** | 모의고사 점수가 계속 안 오르면 공부 방식 그만 | 검증 손실이 한동안 안 좋아지면 학습을 멈추는 것 (Day 3 문제 5) |
| **수렴(converge)** | 더 공부해도 점수가 거의 안 변하는 상태 | 손실이 충분히 작아져서 더 고칠 필요가 없는 상태 |
| **토크나이저(tokenizer)** | 문장을 단어 카드로 자르기 | 문장을 모델이 처리할 조각(토큰)으로 나누는 도구 (Day 4 문제 2) |
| **로그(log)** | 공부 일지 | 학습 중에 `epoch 3 loss=0.25`처럼 출력해 두는 기록 (Day 4 문제 4) |

### 학습 루프 = 반복문

딥러닝 학습 코드는 거의 항상 이런 모양입니다.

```python
for epoch in range(num_epochs):        # 문제집을 num_epochs 번 반복해서 푼다
    for batch in data:                 # 문제 묶음을 하나씩 꺼내서
        prediction = model(batch)      # ① 풀어 보고 (예측)
        loss = 채점(prediction, 정답)   # ② 채점하고 (손실 계산)
        파라미터를_조금_고친다(loss)      # ③ 틀린 만큼 고친다 (경사하강법)
    if 검증손실이_한참_안_좋아짐:
        break                          # early stopping
```

아직 실행할 수 있는 코드는 아니지만, **바깥 for = epoch, 안쪽 for = batch, break = early stopping**이라는 구조만 기억하세요. 파이썬만으로 흉내 내 보면 이렇습니다.

```python
loss = 1.0
for epoch in range(1, 6):
    loss = loss * 0.7          # "학습하면 손실이 30%씩 줄어든다"고 가정한 가짜 학습
    print(f"epoch {epoch}: loss={loss:.3f}")
```

```
epoch 1: loss=0.700
epoch 2: loss=0.490
epoch 3: loss=0.343
epoch 4: loss=0.240
epoch 5: loss=0.168
```

### 경사하강법 (문제 5의 배경)

"틀린 만큼 고친다"는 ③을 구체적으로 하는 방법이 **경사하강법(gradient descent)**입니다. 가장 단순한 예로 이해해 봅시다.

- 모델의 파라미터가 숫자 **`w` 하나**뿐이고, 정답은 **w = 3**이라고 합시다.
- 손실은 `loss = (w - 3) ** 2`. w가 3에서 멀수록 손실이 커지고, w = 3이면 0입니다.

```
loss
 9 |*                             *
   |
 4 |     *                   *
   |
 1 |          *         *
 0 +---------------*--------------- w
    0    1    2    3    4    5    6
```

손실 그래프는 **그릇 모양**이고, 우리는 그릇의 **바닥(w = 3)**을 찾고 싶습니다. 그런데 컴퓨터는 그래프 전체를 볼 수 없고, **지금 서 있는 곳의 기울기**만 알 수 있습니다. 눈을 가리고 산을 내려가는 상황과 같습니다. 발밑의 경사만 느끼고, 내리막 쪽으로 한 발씩 걷습니다.

1. **기울기(grad)** 구하기: `grad = 2 * (w - 3)`. 이 식이 어떻게 나왔는지는 미분이라서 Day 60쯤 배웁니다. 지금은 공식으로 받아들이세요.
   - w < 3 (바닥 왼쪽) → grad가 음수 → 오른쪽이 내리막
   - w > 3 (바닥 오른쪽) → grad가 양수 → 왼쪽이 내리막
2. **한 발 이동**: `w = w - lr * grad`. 기울기의 **반대 방향**으로, 학습률 `lr`만큼 비례해서 움직입니다.

w = 0, lr = 0.1에서 시작하면 실제로 이렇게 움직입니다.

| 업데이트 횟수 | w | loss = (w-3)² | grad = 2(w-3) | 다음 w = w - 0.1 × grad |
| --- | --- | --- | --- | --- |
| 0 (처음) | 0.0 | 9.0 | -6.0 | 0 - 0.1×(-6.0) = **0.6** |
| 1 | 0.6 | 5.76 | -4.8 | 0.6 + 0.48 = **1.08** |
| 2 | 1.08 | 3.6864 | -3.84 | 1.08 + 0.384 = **1.464** |
| 3 | 1.464 | 2.359… | … | … |

w가 3을 향해 다가가고 손실이 줄어듭니다. 이걸 손실이 `tol`(허용 오차, 예: 0.01)보다 작아질 때까지 반복하면 "수렴했다"고 말합니다. **몇 번 반복해야 할지 미리 모르니까** while(또는 상한이 있는 for + break)이 딱 맞는 상황입니다.

### 학습률이 너무 크면?

| lr | 처음 몇 번의 w | 결과 |
| --- | --- | --- |
| 0.1 | 0 → 0.6 → 1.08 → 1.464 … | 천천히 바닥에 도착 |
| 0.5 | 0 → 3 | 한 번에 바닥 (이 문제에서만 생기는 특별한 경우) |
| 1.0 | 0 → 6 → 0 → 6 … | 바닥을 건너뛰고 양쪽 벽을 왔다 갔다 (**진동**) |
| 1.1 | 0 → 6.6 → -1.32 → … | 점점 더 멀리 튕겨 나감 (**발산**) |

한 발이 너무 크면 그릇 바닥을 지나쳐 반대편 벽으로 넘어갑니다. 그래서 실제 학습에서는 lr을 0.001처럼 작게 잡는 경우가 많습니다. 하지만 너무 작으면 바닥까지 너무 오래 걸립니다. 이게 바로 문제 5에 `max_steps`(최대 반복 횟수) 안전장치가 필요한 이유입니다. 수렴하지 않는 경우에도 반복이 언젠가는 끝나야 하니까요.

## 1. for 와 range

```python
for i in range(3):          # 0, 1, 2  ← 3은 포함하지 않는다
    print(i, end=" ")
print()                     # 0 1 2

for i in range(1, 6):       # 1 ~ 5    ← range(start, stop): stop 은 미포함
    print(i, end=" ")
print()                     # 1 2 3 4 5

for i in range(10, 0, -3):  # 10, 7, 4, 1  ← range(start, stop, step)
    print(i, end=" ")
print()                     # 10 7 4 1

print(list(range(5, 5)))    # []  ← start >= stop 이면 한 번도 안 돈다
```

`range(a, b)`는 **a 이상 b 미만**입니다. 길이는 `b - a`. "1부터 N까지"는 `range(1, N + 1)`입니다.

`for`는 range만이 아니라 **하나씩 꺼낼 수 있는 것**(iterable)이면 무엇이든 돕니다. 문자열은 글자 하나씩 꺼내집니다.

```python
for ch in "AI!":
    print(ch, end="|")
print()                     # A|I|!|
```

## 2. 누적 패턴: 반복 전에 초기화, 반복 안에서 갱신

```python
total = 0                   # ① 반복 전에 시작값
for x in range(1, 5):
    total += x              # ② 매번 갱신 (total = total + x)
print(total)                # 10   ③ 반복이 끝난 뒤 사용

count = 0
for ch in "banana":
    if ch == "a":
        count += 1
print(count)                # 3
```

AI 코드에서 "epoch 동안 배치별 손실을 다 더해서 → 배치 수로 나눠 평균 손실 구하기"가 정확히 이 패턴입니다.

## 3. while: 조건이 참인 동안 반복

```python
loss = 1.0
epoch = 0
while loss >= 0.1:          # 매 반복 "시작 전에" 조건을 다시 검사
    loss *= 0.5
    epoch += 1
print(epoch, loss)          # 4 0.0625
```

반복 횟수를 **미리 모를 때** `while`을 씁니다. 반복 안에서 조건에 쓰인 값(`loss`)이 바뀌지 않으면 영원히 끝나지 않습니다(무한 루프, `Ctrl+C`로 중단).

## 4. break 와 continue

```python
for ch in "ab3cd#ef":
    if ch == "#":
        break               # 반복문 전체를 즉시 탈출
    if ch == "3":
        continue            # 이번 회차만 건너뛰고 다음 회차로
    print(ch, end="")
print()                     # abcd
```

- `break`: 가장 가까운 반복문을 **끝낸다**. (AI: early stopping, "충분히 좋아졌으니 그만")
- `continue`: 아래 코드를 건너뛰고 **다음 회차로** 간다. (AI: 깨진 데이터 샘플은 건너뛰기)

## 5. for-else / while-else

`else` 블록은 **break 없이 반복이 끝까지 돌았을 때만** 실행됩니다. "찾다가 못 찾음"을 표현할 때 씁니다.

```python
n = 7
for d in range(2, n):
    if n % d == 0:
        print(n, "는 약수", d, "가 있음")
        break
else:                       # break 가 한 번도 안 일어났을 때
    print(n, "는 소수")      # 7 는 소수
```

if의 else와 헷갈리기 쉬워서 "no-break"라고 읽으면 기억하기 쉽습니다. 함수 안이라면 `return`으로 같은 일을 할 수도 있습니다.

```python
def has_zero(text):
    for ch in text:
        if ch == "0":
            return True     # 찾자마자 함수 종료 (break + 결과 반환)
    return False            # 반복을 다 돌았는데 못 찾음

print(has_zero("1205"), has_zero("123"))   # True False
```

AI에서는 "최대 epoch 안에 목표 손실에 도달했나? 끝까지 못 했으면 경고"처럼 쓸 수 있습니다.

## 6. 맛보기: 문자 비교

문자열도 `<`, `<=`로 비교할 수 있고, 연쇄 비교도 됩니다. 숫자 글자인지 확인할 때 유용합니다.

```python
ch = "7"
print("0" <= ch <= "9")     # True
print("0" <= "a" <= "9")    # False
print(ch.isdigit())         # True  ← 같은 일을 하는 문자열 메서드 (Day 5 이후 자세히)
```

## 자주 하는 실수

1. **range 끝 off-by-one**: `range(1, n)`은 n을 포함하지 않습니다. 1~n이 필요하면 `range(1, n + 1)`.
2. **누적 변수를 반복 안에서 초기화**: `for` 안에 `total = 0`을 두면 매번 0으로 돌아가서 마지막 값만 남습니다.
3. **while 조건 값을 갱신하지 않음**: `while loss >= 0.01:` 안에서 `loss`를 바꾸지 않으면 무한 루프입니다. 위 학습률 표처럼 **영원히 수렴하지 않는 경우도 있으니**, `max_steps` 같은 상한을 함께 두는 습관을 들이세요.

## 내부 동작 원리: for 는 "다음 거 줘"를 반복하는 while 이다

`for x in obj:`는 내부적으로 ① `it = iter(obj)`로 **이터레이터**를 얻고, ② `x = next(it)`를 반복 호출하다가, ③ 더 꺼낼 게 없을 때 이터레이터가 던지는 `StopIteration` 예외를 받아 조용히 반복을 끝냅니다. 즉 for문은 "다음 거 줘"를 반복하는 while문을 짧게 쓴 것입니다. `range`는 숫자를 미리 만들어 두는 목록이 아니라 `start`, `stop`, `step` 세 값만 기억하고 `next`가 불릴 때마다 다음 숫자를 계산하는 객체라서, `range(10**12)`도 메모리를 거의 쓰지 않습니다. 이 성질이 AI에서 중요한 이유가 있습니다. 이미지 100만 장을 한꺼번에 메모리에 올리면 컴퓨터가 버티지 못하는데, PyTorch의 `DataLoader`도 이터레이터라서 `for batch in loader:`로 돌 때 **필요한 배치만 그때그때** 디스크에서 읽어 만들어 냅니다. for-else의 `else`는 ③의 "정상 종료" 경로에만 붙어 있는 코드라서, `break`로 빠져나가면 그 경로를 건너뛰어 실행되지 않습니다.

```python
it = iter("AI")
print(next(it), next(it))   # A I
# next(it)                  # StopIteration  ← for 는 이 예외를 보고 멈춘다

r = range(0, 10**12, 2)
print(r[3], len(r))         # 6 500000000000  ← 숫자를 만들지 않고 계산만 한다
```
